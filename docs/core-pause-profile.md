# Core cooperative native pause profile

`millforge-base.cooperative-local-io.v1` controls one already-started invocation in
an actual stock Millforge base live runner. Core owns its daemon thread, native
session, cancellation token and event loop. The thread lives in the Core process.
Killing that process loses the continuation. Restarting a requesting CLI does not.

The production factory requires exact owned clock, cancellation and secret
resolver types and the default artifact writer. The owned HTTP transport targets
an explicit loopback endpoint. A caller profile name or injected service cannot
grant eligibility. External HTTP responses in the CORE-I01E proof are scripted.
No paid provider or released OS integration is qualified by that proof.

The qualified effect scope includes owned model HTTP requests and stock `read`
and `write` on ordinary files within the resolved local workspace. Runtime path
checks exclude symlinks, escaping paths, devices, FIFOs, nonlocal filesystems and
unproved filesystem paths from native qualification. The executor verifies the actual stock bindings.
The filesystem observer admits only local macOS APFS/HFS volumes. Other
platforms retain ordinary execution but cannot admit this native pause profile.
These checks do not create a general filesystem sandbox.

Eligibility, native control reservation and effect entry share the invocation's
lock. If pause admission wins, unsupported work cannot enter before exact release.
If unsupported entry wins, the gate removes qualification before entry and later
pause admission refuses.

After a legal release, ordinary base execution may enter
unsupported work. That removes future native qualification without creating a new
execution hold. Its ordinary completion authority remains intact. Native retirement
then refuses without fresh effect and descendant evidence.

Core commits accepted pending intent before signalling the owner. Native waits
occur outside SQL transactions. A zero active-effect count does not acknowledge
pause: the actual guarded invocation must park at a checkpoint. Checkpoints occur
at loop iteration entry and before each tool-batch member. They preserve the
existing coroutine, messages, retry state, deadline, session and token authority.
An in-flight effect must settle before the next checkpoint can acknowledge pause.

Core appends the applied result after verifying the parked witness. During hold,
the checkpoint checks existing cancellation and deadlines. Resume releases only
the exact pause identifier. An additional barrier prevents wake into effects until
Core has committed the resume settlement. Same-key replay retains the original
receipt and observes later results.

Cancellation, timeout and finalization invalidate a durable held witness before
writeback effects. `invalidation_pending` records an unfinished invalidation and
refuses new admission or retirement. Failed journal writes prevent effect entry.
Once the actual native event loop ends, Core removes the exact owner registration
and detaches its journal. Live pending and held owners remain registered.

A held witness establishes no admitted OS descendants within this profile.
Unsupported shell execution can create an owned child and removes that guarantee.
The proof exercises both ordering directions with a real child. Fixture teardown
of that child is explicitly separate from product recovery.

Fresh `runs.recover` with `mode=retire_native_continuation` can retire an absent
owner only with an unbroken, exact parked witness and fresh process-birth evidence.
The old session becomes lost and remains nonrunnable. History and budgets remain.
For this no-descendant held profile, cleanup is verified `not_required`. Unknown
effects, pending work, invalidation or unsupported descendants refuse retirement.
This operation grants no retry, replay, workflow recovery, daemon socket cleanup,
`stopped_clean` classification or daemon relaunch.

For an unsafe retirement request, Core can separately record exact owner loss
under the original accepted control. The refused retirement receipt links that
observation. Replay can finish recording the old session as lost after caller
loss. Exact run/session/control and source fences precede these state changes.
No unsafe retirement is admitted by this independent aftermath reconciliation.
